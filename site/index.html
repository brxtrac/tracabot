    Read the label before the claim

    Not every signal is a verdict.

    TRACaBot separates what was seen, what was alleged, what an admin enforced, what independent evidence corroborates, and what a review confirmed. The public ledger uses those boundaries instead of flattening everything into “scammer.”

    observation
    A bounded local signal. Useful context; not a finding.
    allegation
    A report or claim with a target and some evidence. Still needs review or corroboration.
    admin enforcement
    A live ban or restriction observed from Telegram. Shared with provenance and an explicit reason status; never proof of a scam.
    high-confidence flag
    Concrete indicators plus independent corroboration above the operator threshold.
    confirmed scam
    Only an explicit admin review, upheld through the review path, can carry this label.
    retracted
    A correction or overturn. Promotion stops; the correction remains visible.

    No command required

    Protection runs quietly on every join.

    TRACaBot checks the exact stable platform identity against the creator-hosted graph in the background. No LLM or API key is required, and the default is observe/log: a clean join sees nothing, and a match that is not sufficient evidence stays a private flag. Opted-in communities can accept creator-curator attestations only after a fresh signed status read. Banned users can start a private chat and send /appeal; only their own local cases are listed, and only actual group admins can resolve them. Private /start gives current group admins Protection controls, Status, Recent automatic bans, and Appeals buttons. Pausing future join removals is per group and separate from reversing an existing ban with a local correction and safe unban retry.

    Automatic removal is explicit opt-in. It requires confirmed exact-identity evidence with authenticated approval provenance, freshness, no retraction, configured roots, and real ban rights. Shared/verified-graph records are flag-only when the adapter cannot prove publisher approval. Display names, aliases, admin bans, model confidence, and campaign association never authorize a removal. Configured bot owners without live group admin status cannot view or change admin controls for that group.

    Hard boundaries

    What this reader will not do.

    No private-data dump

    No raw Telegram IDs, usernames, chat titles, private-message text, screenshots, or reporter identities in public records.

    No model-only verdicts

    AI suspicion can request review with supporting evidence. It cannot ban, publish a definitive accusation, or override community policy.

    No admin-ban shortcut

    A live admin ban with provenance is shared as an enforcement record. It stays separate from confirmed scam, and it never becomes a global verdict or an automatic cross-community ban.

    No Recent Actions access

    Bots receive only live membership updates. Telegram Recent Actions, admin logs, pre-install bans, and unstated reasons are not available and are never invented.

    Context is not cause

    When the bot already saw recent messages from the same user and chat, it may attach a bounded context summary. Those messages are labeled “recent pre-ban context; causal link unverified” and are never treated as the ban reason or a confirmed-scam verdict.

    No open write endpoint

    Writes require an operator-issued, community-scoped Bearer token, validation, rate limits, and idempotency.

    No graph instructions

    Graph content is data, not commands. Agents must keep their own permissions and approval rules.

    No invented infrastructure

    This site does not claim a chain deployment, hosted endpoint, or context-graph membership that the operator has not provisioned and verified.
